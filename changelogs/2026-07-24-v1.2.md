- 子矩形 R 角按 `max(0, 父R − 边距)` 公式自动算
- 默认开启，可关闭
- onApply / applyPipette 末尾 hook：检测 layout 父 → 同步子 R 角

### 2.4 手动设置父子 ⏳ 进行中

- rows × cols 数字输入实时校验子数量

## 4. 数学公式

设父 W×H、边距 p、间距 g、行/列 r/c：

- 子尺寸：
  - `subW = (W - 2p - (c-1)g) / c`
  - `subH = (H - 2p - (r-1)g) / r`
- 子位置（row-major 顺序 `idx = i*c + j`）：
  - `subLeft[i,j] = parentLeft + p + j*(subW + g)`
  - `subTop[i,j] = parentTop + p + i*(subH + g)`
- R 角联动：`subR = max(0, parentR - p)`（clamp ≥ 0，且不能超过子短边一半）

约束：
- `2p + (c-1)g <= W`（不能比父还宽）
- `2p + (r-1)g <= H`（不能比父还高）
- 超过约束 → 警告「边距/间距太大，挤不下」

## 6. 实时同步机制

```
[滑块/输入 input 事件]
  → scheduleLayoutApply()  (50ms 节流)
    → applyLayoutFromUI()
      → applyLayoutToChildren()  (一次 PowerPoint.run 事务)
        → 读父 → 算 layout → 写所有子 + 写父 tag
      → refreshSelection()  (UI 同步)
        → syncLayoutChildrenRIfNeeded()  (R 角联动 hook)
```

- onApply / applyPipette 末尾额外调 `syncLayoutChildrenRIfNeeded()`
- 父 R 角被 task pane 改 → 子 R 角自动跟随

## 16. v1.2.6 修 driver.adjFraction load 坑（v1.2.5 烟囱测试时暴露）

**问题**：用户跑烟囱测试选 3 个组合后，lock monitor 持续刷屏
```
[lockMonitor] skip id=N: 尚未加载结果对象的值。请先调用相关请求上下文上的 "context.sync()"，然后再读取值属性。
```

**根因**：
- 集合层 `load('items/adjustments')` 只填 `.count`，**不填 `.value`**（AGENTS.md 4.4 早就记了这个坑）
- v1.2.3 迁移 monitor 时只 load `items/adjustments`，没加 per-shape `load('items/value')`
- `driver.adjFraction` 内部 `s.adjustments.get(0).value` 抛异常
- monitor 的 try/catch 把异常吞了，每 10ms 刷一行 skip log

**修法**（双保险）：
1. **driver.adjFraction defensive**：内部包 try/catch，value 没 load 返回 0（不 throw）—— driver API 永不 throw 契约
2. **driver 加 loadAdjValue(s) 辅助**：`s.adjustments.load('items/value')` 的薄封装
3. **monitor / smoke test 改用两阶段 load**：
   ```js
   driver.load(sel, 'items/id, items/.../adjustments');
   await driver.sync();
   for (const sh of sel.items) {
     if (driver.isRoundRect(sh)) driver.loadAdjValue(sh);  // per-shape
   }
   await driver.sync();
   // 现在 driver.adjFraction(sh) 不会 throw 了
   ```

**driver 方法数**：15 → 16（多了 `loadAdjValue`）

**测试**：230/230 全过（新增 2 个：adjFraction defensive + loadAdjValue）

**AGENTS.md 新增 4.2.1 节**记录这个坑，避免下次再踩

## 17. v1.2.7 修 setAdjFraction 读不回 + lock monitor GeneralException（v1.2.6 烟囱测试暴露）

**问题**：v1.2.6 烟囱测试 13 通过 1 失败 + lock monitor 持续报 GeneralException。

**两个真问题**：

### 问题 1：setAdjFraction 写完读不回来
```
[smoke] ❌ setAdjFraction + sync + adjFraction: wrote 0.5, read back 0.0000 (orig was 0)
```
- **根因**：`sh.adjustments.get(0)` 返回**新** ClientResult 代理，set+sync 之后再 `get(0).value` 拿新代理，value 没填
- **解法**：先 `get(0)` 存变量，再 set + sync，再读**那个**变量（v1.0 working 模式）

### 问题 2：lock monitor 批量 per-shape load 炸了
```
[18:48:34] lock monitor error: ... ShapeScopedCollection.getItem ... adjustments.load(["value"])
```
- **根因**：v1.2.6 monitor 用了「集合层 load → per-shape `adjustments.load('items/value')` 排队 → 全局 sync」
  - 第二个 shape 的 `getItem` 在 queue 里抛 `GeneralException`（Mac LTSC 不支持批量 per-shape load 队列）
- **解法**：v1.0 模式——per-shape `get(0)` + per-shape sync（慢但正确，N syncs for N shapes）

**改动**：
- `dialog.js` monitorTick：改回 v1.0 per-shape sync 模式
- `dialog.js` runDriverSmokeTest step 6：先 get(0) 存变量再 set+sync+读
- `ppt-driver.js` 保留 `loadAdjValue` 辅助（单 shape 情况 OK，文档写明不能批量用）
- `AGENTS.md` 4.2.1 节加入「批量 per-shape load 后单 sync 炸」的禁止项

**测试**：230/230 全过（v1.2.6 → v1.2.7 无新测试，纯修复）

await ctx.sync();

// ✅ v1.2.9 对的（每次读 fresh get 新 proxy）：
sh.adjustments.set(0, 0.5);
await ctx.sync();
sh.adjustments.load('items/value');
await ctx.sync();
const v = sh.adjustments.get(0).value;  // fresh get
