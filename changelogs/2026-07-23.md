# 2026-07-23

## v1.0 — 正式版

macOS PowerPoint 加载项，让用户用 **厘米** 或 **百分比** 设置圆角矩形的 R 角。
**task pane** 形式（侧边栏），lock 持久化用 `shape.tags`（跟 .pptx 文件走）。

### 主要功能

- **R 角数值设置**：cm / % 两种单位，iOS 风格 segmented control 切换
- **多选支持**：`getSelectedShapes()` 逐个 set
- **锁定 R 角**：按厘米值保持；改变形状大小时自动按比例调整（10ms 轮询 + 4 次稳定检测）
- **最近 5 次历史**：纯内存（关掉 task pane 就没），分段按钮样式，可点击填入
- **实时选区变化**：`DocumentSelectionChanged` 自动 refresh
- **非圆角矩形检测**：UI 标记 + 跳过 apply

### 关键设计决策

1. **纯 Office.js 路线**：所有读写在 PowerPoint 进程内完成，无 server 端 .pptx 处理
2. **task pane 形式**（不是 dialog）：dialog 上下文 API 限制太多，task pane 可以用 `shape.tags`
3. **`shape.tags` 存 lock**：Mac LTSC 上 `customProperties` / `customXmlParts` 都不可用
4. **history 纯内存**：简单可靠，不跟文件走（用户主动决定保留 vs. 关掉就没）
5. **本地静态 server**（~60 行）：只为 task pane 提供 HTML/CSS/JS 资源

### 关键修复（v1.0 历程）

1. **`Adjustments.value` 单位是 0~1，不是 0~50000**（`3a92e17`）
   - Mac LTSC `get(0).value` 返回 0~1 的小数比例（OOXML 值 ÷ 50000）
   - 旧代码 `ADJ_SCALE = 100000` → 圆角全显示成 0.00
   - 改 `ADJ_SCALE = 1` 后正确

2. **`adjustments.get(0)` 是 ClientResult 代理**（`70c1683` / `bf83636`）
   - 不能调 `.load('value')`（报 `load is not a function`）
   - 直接 `.value` 读

3. **task pane `shapes.load` 不自动填 adjustments 子项**（`c666fb1`）
   - 必须显式 `sh.adjustments.load('items/value')` + sync
   - dialog 上下文可能不必要，task pane 必须显式 load

4. **`customXmlParts` 在 Mac LTSC task pane 也不可用**（`2db10d9` 验证）
   - 不是 dialog 特有的限制，task pane 也一样
   - 最终方案：`shape.tags` 存 lock

5. **lock 跨 session 验证**（`bf83636`）
   - 锁定 → Cmd+S → Cmd+Q → 重开同一个 .pptx → lock 还在
   - 真的跟 .pptx 文件走

### 踩坑过程

调试面板最终打出来的 `adjustments.get(0).value = 0.17183` 是 v1.0 第一个 bug 的
关键线索。中间误以为是 `load('value')` 没调（试了 → 报 `load is not a function`
→ 说明 `get(0)` 返回的是 ClientResult 不是 ClientObject）→ 回退到直接 `.value`
→ 看到 0.17183 这个非 0 也非 50000 量级的值 → 意识到单位不对 → 改 ADJ_SCALE=1。

task pane 改造时，误以为 `get(0).value` 在 task pane 也直接能读，**又踩了一次
"load is not a function" 的坑**，撤回到直接 `.value`。

切到 task pane 后发现 `customXmlParts` 还是不可用，**再次踩了 fallback 链的坑**。
最终落到 `shape.tags` 方案——之前在 lock 早期版本就考虑过，但当时 Office.js 1.10
未确认兼容。Mac LTSC 16.111 实测能用。
