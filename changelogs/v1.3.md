### 1.2 修 bug #1：样式刷吸取后无法刷入 ✅

**根因**：`applyPipetteToSelection` 之前调的是 `writeRadiusToShape`（v1.2.2 之前的兼容版），不走 driver，行为跟 `radius-core.writeRadius` 重复。在某些 Mac LTSC 场景下这个老函数会刷不进去。

**修法**：把整个 `applyPipetteToSelection` 改成调 `radius-core.applyPickedToSelection`（driver 版，单 PowerPoint.run 完成拦截 + 写 R 角 + 刷 strict）。

### 1.3 修 bug #2 + 新发现的子 bug：4 个子只写 2 个 ✅

**用户实测现象**：
- 2×2 布局
- 在 PPT 里直接拖父的 R 角黄色滑块（不走 task pane onApply）
- 之前：完全没联动（v1.2.1 报过）
- 修完 v1.3.6 第一次跑：上面 2 个子变了，下面 2 个没变

**根因（v1.2 已知）**：拖父 R 角不在 task pane onApply 路径上，syncLayoutChildrenRIfNeeded 没被 hook 触发。已加 `monitorTick` 末尾检测 + 节流触发。

**新发现的根因（v1.3.6 修）**：
- `radius-core.syncLayoutChildrenR` / `applyLayout` 内部调 `writeRadius`，而 `writeRadius` 内部 `readTag` 调 `ctx.sync()`。
- 4 个子 = 4 次 `readTag + ctx.sync()` + 4 次 `setAdjFraction`。
- **Mac LTSC 真实 PPT 上 per-call sync 在 for 循环内累积**（v1.2.6 注释过这个坑），后几个 shape 的 `setAdjFraction` 失败/丢失。
- 表现为：4 个子只写 2 个（z-order 关系可能也有关：上面 2 个写成功，下面 2 个写丢失）。
- mock harness 不模拟这个 PowerPoint 内部状态，所以单元测试一直过、实测一直炸。

**修法**（核心）：
- 走 `driver.readTagsBulk` 一次拿全部 tag（不调 per-shape ctx.sync）—— 这个函数 v1.2 期间已经加到 driver / test-harness，**但 radius-core 一直没用**。
- `writeRadius` 加 `opts.knownLockState` 入口，caller 已知 lock + strict 就不调 readTag。
- `syncLayoutChildrenR` / `applyLayout` 改成：一次 load + sync 拿全部 + readTagsBulk + 写所有 setAdjFraction + final sync。

**单测覆盖**：
- `bug #6 子 bug：syncLayoutChildrenR 写 4 个子（2×2）→ 全部写进去`（验证 4 个子 adjFraction = 0.5）
- `bug #6 子 bug：applyLayout 写 4 个子（2×2）→ 全部写进去`（同样验证）
- `bug #6 子 bug：writeRadius opts.knownLockState 跳过 per-call readTag`（验证 call 计数 = 0 readTag）

### 1.4 修 bug #3：lockMonitor 偶发 GeneralException ✅

**根因**：跟 bug #2 同一类坑。`monitorTick` 1365-1459 行的 for 循环里**每个 shape 都 `await driver.sync()`**（per-shape get(0) + per-shape sync 模式，v1.0 写法）。多个 shape = 多次 ctx.sync()，Mac LTSC 偶发 `GeneralException`。

**修法**：跟 bug #2 同款——`monitorTick` 改成 collection-level load `items/adjustments/items/value` + 1 次 sync + readTagsBulk + 全部 shape 直接读 value。

### 1.5 修 bug #4：调试 log 清掉 ✅

清掉的 log：

- `[syncLayoutChildrenR] OUTER ERROR`
- `[scheduleParentRSync] error`
- `[refreshSelection] 父 X 的 Y 个子已不在当前 slide ...`（保留 stale 提示给用户，但 log 删了）
- `[lockMonitor] skip id=...`（catch 块 silent skip）
- `[monitorTick] detectLayoutParentChanges error`（catch 块 silent skip）
- `lock monitor error`（catch 块 silent skip）

**保留的 log**（防误触铁律要求 catch 块 log 异常 message，v1.2.1 教训是吞了根因找了一晚上）：

## 2. radius-core 新增 8 个 driver 版函数

| 函数 | 行为 | 替换 dialog.js 的 |
| --- | --- | --- |
| `loadLayoutTags(driver, selectedShapes)` | 读 layout tag + stale 检测 | `loadLayoutTagsViaTags` 50 行 → 13 行 wrapper |
| `saveLayoutTags(driver, slide, parentId, params, childIds)` | 写父+子 tag，自动过滤 stale | `saveLayoutTags` 38 行 → 12 行 wrapper |
| `pickupFromSelection(driver, selectedShapes)` | 吸源 R 角 + strict | `pickupFromSelection` 60 行 → 22 行 |
| `applyPickedToSelection(driver, selectedShapes, source, opts)` | 刷 R 角 + 拦截 + 刷 strict | `applyPipetteToSelection` 120 行 → 50 行 |
| `detectLayoutParentChanges(knownCmMap, selectedShapes)` | 纯函数：检测 layout 父 R 角变化 | monitorTick 末尾的 inline 逻辑 |
| `parseLayoutParentTagValue(tagValue)` | 纯函数：JSON.parse 父 tag（带兼容性 + 容错）| dialog.js 内联 JSON.parse |
| `detectStaleChildrenInLayout(parsedTag, selectedShapeIds)` | 纯函数：分离 valid + stale 子 | dialog.js 内联 filter |
| `pushHistory(history, value, unit, maxLen)` | 纯函数：去重 + unshift + slice | `pushHistory` 内联 5 行 |

`writeRadius` 新增 `opts.knownLockState` 入口（caller 已知 lock + strict 就跳过 readTag + sync 累积）。

## 6. Mac LTSC 教训新增（v1.3.6）

1. **per-call sync 在 for 循环内累积**：v1.2 期间 driver 加了 `readTagsBulk` 解决 test harness 的 per-call sync 累积，但 radius-core 一直没接入。**v1.3.6 才真正用上**。
2. **Mac LTSC 真实跑跟 mock 不一致**：mock 跑得通的代码（4 个子全写）在真实 PPT 上挂（4 个子只写 2 个）。**信任单元测试**要看单元测试有没有模拟到真实场景——这次单元测试虽然过了，但 `bug #2 4 个子只写 2 个` 是真实 PPT 实测才暴露的 mock 模拟不到的 bug。
3. **driver API 契约**：driver 加新方法（readTagsBulk）后，业务层（radius-core）不一定马上接入。**v1.3.6 用 oncall 时机接入了**——下次新加 driver 方法要检查所有 radius-core 路径是否都接入了。
