# 2026-07-23

## v1.1 — 批量化的核心闭环 + 锁定分两态

让 "R 角统一" 从「一个个设」升级为「按设计意图批量设」。
在 v1.0 之上加两个高频功能（**预设库** + **R 角样式刷**），
同时把 "锁定" 拆成两个独立开关（「使用数值固定 R 角」按钮 + 「防误触」toggle）。

### 主要功能

#### 1. R 角预设库（5 槽位）

- 5 个用户自定义预设，**纯内存**（session 内有效，关掉 task pane 失效）
- 每个预设：可重命名 + 数值（cm/% 都行，按 number input 解读）+ 应用按钮 + 删除按钮
- 「+ 保存当前 R 角」按钮：优先用选中 roundRect 的 R 角，否则用输入框值
- 应用预设：自动切到对应单位 + 写入输入框 + 触发 `onApply()`，复用 v1.0 pipeline

#### 2. R 角样式刷（idle / sourcing / brushing 状态机）

- **idle**：默认状态，按钮显示「吸取 R 角」
- **sourcing**：点按钮进入，黄色脉冲提示。在 PPT 里点 1 个 roundRect 吸取其 R 角
- **brushing**：吸取成功后进入，蓝色脉冲提示。再选其他 roundRect → 自动套用相同 R 角
- 任何时候再点按钮 → 退出样式刷
- 接管 `DocumentSelectionChanged` 事件分发（idle → refreshSelection；非 idle → pipette 逻辑）
- 「刷防误触状态」checkbox：勾选时把源形状的 strict 状态 copy 到目标

#### 3. 锁定分两态：独立开关

v1.0 是单一「固定 R 角」按钮，v1.1 拆成两个独立开关：

| 开关 | 行为 |
| --- | --- |
| 「使用数值固定 R 角」按钮 | 写 fixed value（cm）→ PPT 内拖尺寸反算回 fixed value；拖 R 角滑块视作主动改（更新 fixed value） |
| 「防误触」toggle | 拒绝 task pane 改值（onApply 拦截） + PPT 内拖 R 角滑块反算回当前值 |

新设计要点：
- **防误触独立**：开启时如果形状还没 lock，自动用当前 R 角作 fixed value（写 lock + strict 两个 tag）
- **防误触关闭**：只删 strict tag，保留 lock tag（fixed value 仍可用）
- **关闭「使用数值固定 R 角」**：同时清掉 strict（因为反算目标没了）
- R 角 = 0 或未知时开启防误触：拒绝 + 提示（没法设 fixed value）

### 重要 bug 修复

样式刷开发过程中遇到两个非平凡 bug：

1. **`updateLockTagForShape` 误删 lock tag**：第二次循环（写 strict）传 `cm = null`，原实现走 `delete(LOCK_TAG_KEY)` 分支，把第一次循环刚写的 lock tag 顺手删了，导致「已 lock + 防误触」目标变成「没 lock + 防误触」，UI 上 toggle 因为 `updateStrictToggle` 要求 `allLocked` 才显示开启，看上去就是 "防误触没刷新"。
   - 修复：给 `updateLockTagForShape` 加 `undefined = 不动` 语义，cm 和 isStrict 各自独立控制

2. **`applyPipetteToSelection` 拦截误命中**：brushing 状态下 `DocumentSelectionChanged` 不会调 `refreshSelection`，所以 `selectedShapes` 内存残留之前选中的形状（包括他们的 strict 状态）。如果之前某次样式刷把 strict tag 写到了 X，后来 X 退出选区，`selectedShapes` 内存里 X.strictLocked 还是 true，但 PPT 文件里 X 早没 strict tag 了。下次选新目标 Y，拦截时 `selectedShapes.filter(s.strictLocked)` 命中残留的 X，报错 "目标启用了防误触" 而实际选的目标 Y 完全没启用。
   - 修复：`applyPipetteToSelection` 步骤 0 自己读选区（含 strict + lock tag），生成 `liveShapes` 数组，拦截和写值都用 `liveShapes`，完全脱离 `selectedShapes` 内存

### 实现要点

1. **样式刷应用顺序（明确两步）**：
   - **步骤 0** 拦截：目标已 strict → 整个拒绝（不论是否勾选「刷防误触状态」）
   - **步骤 1** 第一次 "应用"：刷 R 角到所有目标 + 同步 fixed value（已 lock 的目标）
   - **步骤 2** 第二次 "应用"：根据「刷防误触状态」勾选决定是否把源 strict 状态写到目标
   - **步骤 3** toast + refreshSelection
   两个 "应用" 是独立的 try/catch，错误互不阻断

2. **lock monitor 升级**：区分两种拖动
   - `sizeChanged = wChanged || hChanged` → 拖尺寸手柄立刻反算回 fixed value
   - `aChanged`（仅 adj 变）→ 4 次稳定后视作主动改：strict 反算回去；非 strict 更新 fixed value
   - 第一轮（`lastA == null`）只记录初始状态，避免 idle 兜底误把第一次拖动反算
   - 一直跑（未锁定时也 50ms 一次），更新 `currentCm` + 轻量更新 `#current-radius` + `.shape-r` 文本

3. **预设库复用 `onApply()`**：预设不直接写 adjustments，而是切单位 + 写输入框 + 调 `onApply()`。这样 history 记录、shape 列表更新、toast 全部自动复用

4. **样式刷不依赖 `selectedShapes` 内存**：`pickupFromSelection` 和 `applyPipetteToSelection` 都自己跑 `PowerPoint.run` 读选区，避免和 `refreshSelection` 的内存更新时机冲突

5. **DocumentSelectionChanged 三态分发**：
   ```js
   () => {
     if (pipetteState === 'idle') {
       refreshSelection();
     } else {
       onSelectionChangedForPipette();
     }
   }
   ```

6. **lock tag key**：
   - `LOCK_TAG_KEY = 'radiusLock_v1'` → 存 fixed value（cm，string）
   - `LOCK_STRICT_TAG_KEY = 'radiusLockStrict_v1'` → 防误触开关（'1' = 开）
